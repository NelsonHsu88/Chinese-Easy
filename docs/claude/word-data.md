# Word data, story text, HanziStage

Detail split out of CLAUDE.md. Read when working in this area.

## Word data

- **HSK levels are the official HSK 3.0 syllabus** (`scripts/data/hsk30Levels.json`, applied by `node scripts/applyHskLevels.mjs`; re-run after any bank rebuild): 1–6, 7 = the 7–9 band, `hskOfficial: true`. Off-syllabus words get an estimate (never easier than their frequency band or hardest character) and no flag. Labels go through `hskLevelLabel` ("HSK 7–9" / "Rare" above 6). **Commonness is not the level**: search ranks by `commonnessBand` (`lib/frequency.ts`). New Words serves syllabus words first, never below the learner's level; the level-up target counts syllabus words only.
- **Tier 1** `importedWords.json` (25,180, frequency-ranked; SRS, browse, stroke data). **Tier 2** `lookupWords.json` (81,437, id prefix `lk-`, `hskLevel` 7 = "Rare"; search only, packed string split lazily, `warmLookup()` on Dictionary mount). `searchWords` ranks the tiers **in separate passes**; tier 2 only fills an unfilled page. `wordById` falls through to tier 2 so rare words in My Words survive hydrate.
- **Example sentences come from the corpus, except authored ones.** Where a word's corpus sentence shows a different sense from its gloss, a hand-written sentence in `scripts/data/authoredExamples.json` (id → simplified + English) replaces it, marked `example.authored`; `repairExampleSenses.mjs` applies it last and rejects any whose word isn't a token in both scripts or whose English shows none of the listed senses. Multi-character words whose everyday reading is CC-CEDICT's neutral-tone row (告訴 gàosu, 東西 dōngxi) are listed by hand in `NEUTRAL_ROW` (`lib/cedict.mjs`). `repairExampleSenses.mjs` fixes the corpus's script conversion (archaic variants like 咊/㕥, simplified leftovers), keeps a sentence only if the word survives as a token under the app's segmenter **in both scripts** (matched by entry id), and prefers the sentence whose English shows the word's gloss (`senseEvidence.ts`) — re-run after **any** bank rebuild, since verdicts depend on bank composition. Word pages list sentences with `sentencesForWord` (token match, deduped, own sentence first); character pages use `sentencesWith` (substring, deduped).
- **Notes in definitions**: cards drop grammar notes (`withoutGrammarNotes`: "(pronoun)", "(followed by …)") and keep meaning notes; search compares senses without trailing notes, but a leading off-everyday label ("(Cantonese)", "(computing)", `OFF_EVERYDAY_LABEL`) blocks an exact match, and a word found only inside a note ranks with the weakest matches. First-sense tests (`contentRank`, `isTeachableWord`, `isFunctionWord`) look past notes. Saved words and cards store only ids — fixing the bank fixes every learner's deck.
- **"Multiple meanings" tag** (`components/MultipleMeaningsTag.tsx`, colours `multipleMeaningsTag` in `dashboard/tokens.ts`): dictionary result cards (left of Add), the word/character page hero (under the meaning, counted in the glyph's height budget) and the New Words card (top-left corner, so the fixed card height is untouched). `hasMultipleMeanings` merges CC-CEDICT's synonym senses (shared content word or 5-letter root; neighbouring senses both verbs or both not) after dropping commentary/specialist senses; two groups for a character, three for a longer word. Errs towards off (~6% of common words).
- Learning surfaces show `shortGloss(word)` (one chosen sense, `senseScore` — **or the sense the word's example translation shows**, so card and sentence agree; `allSenses` leads with the same), not `word.definition`. `newWordsPool` gates on `isTeachableWord` (no names/surnames/abbreviations); it serves the learner's level + one stretch level first (syllabus words before estimated ones), then harder levels only, commonest first.
- Search ranking ladder is `SCORE` in `lib/dictionary.ts`: English tiers (exact sense > word > word-prefix > letters), ties by sense index (the first `PRIMARY_SENSES` count as one — CEDICT lists synonyms) → `contentRank` → `commonnessBand`. When a query has English exact/word hits, coincidental pinyin matches (`pinyinPartial`/`pinyinContains`) drop below every English rung ("ship" ≠ 視頻 shìpín); `search.test.ts` pins this. Pinyin prefixes count only on syllable boundaries. Plurals folded on the query. Per-entry work cached in a `WeakMap`.
- Radicals: `radicals.ts` (99 taught), `kangxiRadicals.ts` (all 214, naming), `characterRadicals.json` (index). Screens call `radicalFor` only.

## Story text and script

**Segment first, convert second**: `segmentText(text, bank, displayScript)` matches canonical traditional text, then sets each segment's `display`. `TextSegment.text` = canonical (offsets), `display` = draw, `word` = identity. Conversion uses the matched entry's `simplified`, else `scriptConversion.json` (trad→simp only). **Conversion never changes character count** (the build enforces it) — narration offsets, pagination and progress all count canonical characters. The segmenter index holds both scripts, traditional inserted first. Fonts via `hanziFont(script, weight)`, which spells class names as literals (Tailwind scans source); never rely on `font-hanzi`'s fallback chain for script-following text.

## HanziStage (stroke writer)

`hanzi-writer` runs in a `react-native-webview`, one per character. The outline is toggled live (`outline` message), **never via `initKey`** — the flashcard hint turns it on mid-quiz, and a rebuild wiped the strokes and could leave the quiz unstarted; `start` is keyed on a load counter for the same race. `hanziWriterEngine.ts` is **generated** — don't edit. `writerHtml.ts` holds the DOM logic (quiz/demo lifecycle, stroke-placement animation in 1024-unit space, `strokeHint` → gong, `holdCharacterOnComplete` which must apply in **both** quiz and demo branches). Multi-character words hold each finished glyph `CHARACTER_HOLD_MS` (900; flashcards pass 300 via `characterHoldMs`). Stroke data: bundled `src/assets/hanziData.json` (tier 1, both scripts, ~15.8MB), CDN fallback otherwise. Tier 2 is excluded to keep size down; to shrink further, narrow the character set, don't go CDN-only.
